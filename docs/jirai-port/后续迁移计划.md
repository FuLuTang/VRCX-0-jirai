## 本轮已确认实施范围（2026-10-02）

本轮还原三条链路：**增强型信息抓取**、**关系建议／进房 Overlay 提醒及双人关系页收尾**、**灯色占比图**。下文旧顺序以本节为准；功能完成后分别更新结果，不能把计划写成已完成。

- “信息抓取补全”及 Jirai 引入的同步／采集／刷新统一命名为“增强型信息抓取”。包括启动／重连、小时级对账后的补采、资料页按需快照、手动全量与关系建议计算；VRCX-0 的群组、收藏等原有维护不纳入重设计。
- 自动增强抓取默认开启；每次触发强刷，只合并进行中的同账号同对象请求，不增加五分钟复用规则；一次结果同时用于名字、Bio、灯色及状态短语。协调原有 Bio 扫描，避免并行重复扫。
- 工具 → 系统工具与状态栏恢复入口；弹窗展示分层策略、真实逐人进度、失败／缺字段、确认落盘更新和下次运行信息。关闭弹窗后台继续，显式取消才停止。
- 推荐直接适配 VRCX-jirai 的评分、阈值、排序和过滤，不重新设计算法。确认生成手动关系；忽略本次运行有效并按账号隔离。进房提醒默认开启，可关闭，仅真实同房触发并去重。
- 灯色还原按时间分桶堆叠占比图、缩放与数字时长，保留确认在线区间口径；滑条停止一秒后重算，不逐格查询。双人关系补可靠峰值人数与证据措辞。
- 所有旧搜索／搜索框相关内容暂缓。本轮不做自己完整历史视图、多账号或群组／收藏维护重设计。
- 分派采集逻辑、采集界面、关系链路、灯色图表四个 subagent；主代理确定共享接口、审查、统一验证及更新文档。先提交并 push 当前文档盘点，功能另行提交。

## 资料采集的收尾

已有追踪名单、手动工作流、原生 Bio/Status 比较落盘、Online 补线和渐进 Bio 扫描。后续交付按下列小步拆开，每步可独立审查：

1. **同一轮只取一次资料。**目前非好友名单刷新动作先请求一次，后面的资料存档动作再请求一次。合并资料结果的使用路径：更新名字、比较 Bio/灯色、存档和进度共用一次结果。不要把执行了目标数当作成功抓取数。
2. **补真实进度与结果。**workflow 目前只有动作级状态；资料执行器的目标数、Bio/Status 更新数、失败数、缺字段数没有存进 runner 快照。补逐人进度、最终结果和状态栏入口，复用现有任务模型。
3. **接自动触发和定时刷新。**旧任务 08 要求的启动／好友基线刷新后触发尚未落地；当前后台 Bio 扫描仅好友、只 Bio、默认关闭。把显式追踪对象纳入统一采集，协调最短检查间隔、429 暂停、防重入、取消和账号切换；不要把手动 workflow 与渐进扫描简单叠加。
4. **补打开资料页的按需快照。**当前 Profile Bio 观察路径限制当前好友；非好友 Bio／灯色的按需记录仍缺。复用统一比较落盘逻辑，并核对公开 Profile 的 Bio 与用户资料的状态字段来源。与后台和实时事件共同去重。

连带项：自动任务的运行状态应由持续运行的任务持有，资料窗口／workflow 只是显示与操作入口；同时核实数据库写入后 Feed 列表是否收到刷新通知。推荐功能以后复用这些稳定输入。

## 暂不排入近期主线

- 搜索优化：用户 2026-10-02 明确暂不做。最近遇见／世界与本地最新 Bio 匹配仅保留差异和来源；旧版并非全历史任意 Bio 版本搜索。
- 多账号产品：已有进程隔离 RFC；仍需定义日志源归属、认证与合并视图。
- 自动跟随与手动补实例记录：保留旧任务／行为参考，近期优先级低。
- VRCX-Luo 的双人世界排行与拼音搜索：可选增量，区别于 Jirai 必须还原项。
- 好友侧栏上线动画：用户认为收益低，暂不排期。

## 已确认选择与实现约定

- 数据库升级优先沿用 VRCX-0；新增的追踪／人工／历史关系按账号隔离，沿用旧表名与字段语义。
- OLD 日期为最后成功确认时间；失败／拒绝共享不改成新的确认时间；不做 CURRENT 的一次性回填。
- 关系线色：当前普通色、手动绿色、仅历史淡普通色，亮暗主题适配。
- 开发者群自动加入保留且默认开启；无需再次询问这一默认值。
- 旧缺 Bio 字段被误写为空的问题已修复；缺字段保护继续保留。
- 使用当前 React、typed repository、Rust application/persistence 与生成绑定；账号或目标变化时丢弃过期结果。
- 本轮正在实现三条已确认链路；其他暂缓项目不因文档列出而自动纳入范围。
