# 待人工验证清单

更新：2026-10-02。代码基准：`562486290`（`codex/v2.28-jirai-port`），已合入 `VRCX-0/master` 的 `abbdc241c`。

旧文件关于 Linux、没有 Cargo／rustfmt、Rust 从未编译、固定启动提交和“登录后自动完整抓取”的说法已过时。当前是 Windows 工作区；2026-09-30 曾有 Rust 检查、绑定生成与前端完整测试记录。此次合并后的类型检查、76 项相关测试、Rust 格式检查及 Vite 构建通过；全量前端测试因内存不足未完成，Rust 测试／许可证依赖检查受本机代理及离线依赖缓存阻塞。

本清单将“已有功能待实测”与“尚未实现”分开。尚未接通自动完整资料抓取和非好友定时采集；测试时应手动运行 workflow，不应期待登录就完整采集。

## 启动与构建

- [ ] 在已加载 Visual Studio 开发环境的 PowerShell 中，按 README 的步骤执行 `npm run tauri:dev`，确认 Vite 与桌面进程都启动。若端口被占用，先查占用者；不要在两个工作区重复启动。
- [ ] 另验收发布构建的独立启动；开发用 `target/debug/vrcx-0.exe` 可能依赖 Vite，不能拿它证明发布包可双击独立运行。
- [ ] 修复当前 Cargo 网络／代理环境后，补跑合并后的 Rust 检查和资料／账号归属相关测试，复核生成绑定。此前生成过绑定不等于本次已重新验证。
- [ ] 检查第三方许可证阶段是否包含 Rust 依赖；本轮生成脚本跳过了无法获取的 Rust 依赖。

## 备份数据库与账号隔离

- [ ] 使用此前 VRCX-jirai 的备份副本测试导入，记录来源与目标路径；保留原备份。
- [ ] 导入后检查 Feed、游戏日志、Bio 历史、共同好友 OLD、追踪名单与人工关系的实际覆盖，不因某类可读就宣布全部兼容。
- [ ] 账号 A 与 B 分别查看同一目标；历史只来自当前账号及已约定兼容数据，切换时不显示上个账号残留。
- [ ] OLD 日期仍表示最后成功确认时间；失败不刷新日期。CURRENT 未归档的旧数据不要求一次性回填。
