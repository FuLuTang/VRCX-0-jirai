# 08：自动资料抓取

## 目标
恢复旧 Jirai 的启动、好友刷新/重连后自动 Bio + 四种隐私状态抓取；纳入 04 workflow UI。先覆盖好友，06 完成后同一动作自然扩展至 `tracked_nonfriends`。

## 依赖与边界
依赖 04、05；扩展到非好友依赖 06。09 推荐计算只在其自身已实现后作为后续 workflow 动作，不提前调用。不得臆造“七个动作”；未定义动作显示跳过。

## 旧代码可复用分析
核心可直接参照 `infoFetchCoordinator.js:86-196`：防重入、目标去重、逐个 API 获取、一次 500ms 重试、Bio 比较、只记录 `join me/active/ask me/busy` 状态、计数；触发处是 `friendSyncCoordinator.js:20-33,39-80`；UI 参照 `ProfileCompletionDialog.vue` 与 `StatusBar.vue`。把算法顺序和字段搬过来，改为当前 typed repository/Rust commands。

## 子代理引导
“先列出旧 workflow 的真实三步，不要杜撰七步。实现当前账户单例 run/cancel，逐目标节流，结果写入现有 Feed 机制。UI 接 04 的任务状态。不得做 global Vue 风格 reactive state，不得让失败阻断好友初始化。”

## 检查标准
- 启动和好友刷新均触发，但并发触发只跑一轮；
- 目标去重；Bio 仅变化时写入，Status 只写四种主状态变化；
- 单次失败重试一次并继续下一目标；
- 取消停止后续请求，UI 标明取消/跳过；
- 06 后非好友纳入且仍保持 owner scope。
