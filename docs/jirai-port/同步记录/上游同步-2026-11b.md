## 数据库迁移

上游在 `9f48f12d6` 引入了带版本号的迁移（`crates/persistence/src/migration/`，版本记在 `PRAGMA user_version`），v1 把本地收藏迁到 `vrcx0_favorite_group` / `vrcx0_favorite_item`。

jirai 的两张表 **不走版本迁移**，仍是 `CREATE TABLE IF NOT EXISTS`：

- `{prefix}_tracked_nonfriends` 在 `realtime/schema.rs` 的 `ensure_realtime_tables` 里；
- `{prefix}_manual_relations_MANUEL` 在 `database/schema.rs` 的 `ensure_user_store_statements` 里。

原因：

1. 上游 `migrations.rs` 自己规定：只有代价太大、不能每次启动都重做的操作（全表扫描、重建表）才进版本迁移；新建表、加列、建索引这类幂等又便宜的操作，放在 `ensure_*_tables` 里。jirai 的表正是后者。
2. 版本号是线性的、和上游共用。迁移执行器发现数据库版本高于程序支持的版本时会直接报错（`newer than this build supports`）。jirai 一旦占用 v2，以后上游自己的 v2 会和它冲突，用户从 jirai 切回原版时也会被拒绝打开数据库。
3. 版本迁移按 `usr*_<后缀>` 精确匹配表名，v1 只处理收藏表，碰不到 jirai 的表。

上游这次从 `database/schema.rs` 删掉的 132 行全是旧收藏表的建表和索引逻辑（已挪进迁移 v1），和 jirai 无关。
